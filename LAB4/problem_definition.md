# Problem Definition — UCI Adult Income Classification

The goal is to predict whether an individual's annual income exceeds USD 50,000 from demographic, educational, and employment-related attributes in the UCI Adult dataset. The dataset contains 48,842 records and 15 columns, comprising 14 input attributes and one target label, `income`. The task is binary classification: the positive class is `>50K`, and the negative class is `<=50K`.

Input features combine numerical attributes (age, sampling weight `fnlwgt`, years-of-education proxy `education-num`, capital gain, capital loss, and hours worked per week) and categorical attributes (workclass, education, marital status, occupation, relationship, race, sex, and native country). The laboratory's engineering objective is not only prediction, but the creation of a transparent, testable, and reproducible data-processing pipeline that prevents train/test information leakage.

The primary evaluation metrics are positive-class F1 and accuracy on a stratified 30% hold-out test set. Accuracy measures the fraction of correct predictions, while F1 balances precision and recall for people in the `>50K` class. Both metrics are reported because class imbalance can make accuracy alone misleading. A logistic regression classifier provides an interpretable baseline; a second run tests whether the engineered features `capital_net` and `hours_per_age` improve results.

The pipeline must split data before cleaning, learn all imputation, clipping, scaling, and encoding parameters from training data only, and keep the test set untouched by duplicate removal. Input validation must report unexpected types, missing values, and violations of the stated age, working-hours, and capital ranges rather than silently dropping rows. A label audit checks identical feature rows for contradictory income labels and samples 50 observations for dictionary-based review. Finally, the processed training data is serialized deterministically and hashed with SHA256; a YAML metadata file, fitted transformer, and data card document how to reproduce and interpret the results.

This is an educational benchmark, not a validated decision-making tool for hiring, lending, or other consequential decisions. Sensitive demographic features and dataset collection limitations raise fairness and privacy concerns that must be considered before any deployment.
