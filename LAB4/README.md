# Machine Learning — LAB 4: Data Pipeline and Quality

This project implements the tasks in the supplied Vistula Lab 4 manual for the UCI Adult dataset.

## Setup and one-command run

From this directory, after installing Python 3.10+ and dependencies:

```bash
python3 -m venv .venv
source .venv/bin/activate  # Windows: .venv\\Scripts\\activate
python -m pip install -r requirements.txt
python src/main.py
```

The **one-command reproducible execution** is `python src/main.py` after one-time dependency installation. It downloads the Adult dataset from OpenML on the first run (internet required; OpenML service must be available). For offline runs with a previously downloaded, correctly formatted CSV, use `python src/main.py --csv adult.csv`.

## Outputs

Running creates `results/validation_report.json`, `label_audit.json`, `label_review_50.csv`, `preprocessor.joblib`, `model.joblib`, `processed_train.csv`, `processed_train.sha256`, `run_metadata.yaml`, `metrics.json`, and `model_comparison.png`.

Run tests with `python -m unittest discover -s tests -v`.

## Methodology

- Ingest the 48,842-row, 15-column Adult table without modifying its raw values. Validate schema, ranges, missing tokens, and duplicate counts; do not silently remove invalid rows.
- Stratified 70/30 split occurs **before** cleaning; duplicate full-feature rows are removed from training only, and test rows remain untouched.
- Convert `?` to missing; categorical mode and numeric median imputers are fitted on training only.
- Clip numeric features at training 1st/99th percentiles; fit one-hot encoding and scaling on training only.
- Compare logistic regression baseline against a model with `capital_net` and `hours_per_age`. Report held-out accuracy and positive-class F1.
- Audit feature-identical rows with contradictory income labels, and sample 50 raw rows for automated range/dictionary checks. A human should manually verify the 50 sampled rows against the official data dictionary.
- Export a canonical, ordered processed **training** CSV and SHA256; store run configuration and package versions in YAML.

**Important:** The `results/` files are generated by running the script, not pre-filled with fabricated results. OpenML can change availability, and exact metric values depend on package versions.

## Project structure

`src/main.py` — pipeline; `config.yaml` — run settings; `data_card.md` — dataset documentation; `problem_definition.md` — task definition; `tests/` — unit tests; `results/` — generated evidence.

## Status of generated evidence

The actual Adult/OpenML run must be performed on a machine with access to OpenML. Do not submit the results directory as complete until `python src/main.py` succeeds and the generated files have been checked. The 50-row audit is automated; human review remains outstanding.

## Fixes in this release

Default config/output paths resolve from the project root regardless of the current working directory. A regression test covers the feature-name interface. The pipeline was integration-tested with a generated synthetic dataset; those synthetic metrics are **not** included as real Adult results.
